**Not in git, by design:**
- the compiled C++ programs and libraries (`*/bin/*`, `*.so`), which were built by hand on the device;
- `ai_vision/.env`;

Because the running binaries aren't tracked, they can't be proven to match the committed source. Release A rebuilds them in the image, so it is rehearsed on Pashupathi first.

## Running container

- Started by `mantri-container.service` from compose project `mantri`, using `/home/ai/mantri/docker-compose.jetson.yml`.
- Image `:latest`, about 11 GB, **built on the device**. It isn't pinned by digest, and no registry holds it.
- `runtime=nvidia`, `network=host`, `privileged=false`, `restart=unless-stopped`, `entrypoint=/entrypoint.sh`, `workdir=/app`.
- Healthcheck: `/app/docker/healthcheck.sh`, with a 60 s interval, 15 s timeout, 120 s start period and 3 retries. On 2026-09-24 it was healthy, having been up since 2026-09-23 06:14 UTC.
- One container runs three programs, supervised by `wait -n` in `entrypoint.sh`. That already fits ADR 0006 (one app container per Jetson):
  - `mantri_pipeline.py` (Python: events, DB, sync, live stream);
  - `deepstream_unified --monotrack-headless` (C++), which reads `rtsp://localhost:8554/camera-5` from the local MediaMTX;
  - `opsis_runtime` (C++, spectro).
